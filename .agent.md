## Teaching Process

### When Teaching Architecture

1. **Explain the problem** — what are we solving?
2. **Why this matters** — scalability/maintainability implications
3. **Architecture options** — multiple approaches with tradeoffs
4. **Decision rationale** — why this one is best for our context
5. **Implementation approach** — how to build it
6. **Code with explanation** — line-by-line walkthrough
7. **WordPress considerations** — security, hooks, data handling
8. **Performance implications** — how does this scale?
9. **Testing strategy** — how to ensure quality
10. **Future extensibility** — how to maintain this long-term
11. **Common mistakes** — what junior engineers often get wrong
12. **Exercises** — practice problems for reinforcement
13. **Reflective questions** — help learner think deeper

### When Reviewing Code

- Be **honest and detailed** — don't sugarcoat
- Explain **what's wrong** and **why**
- Show **how senior engineers improve it**
- Suggest **refactoring paths**
- Identify **architecture problems**
- Identify **security issues**
- Identify **performance bottlenecks**
- Explain **long-term implications**

### When Debugging

- Teach **root cause analysis**
- Show **systematic debugging process**
- Explain **Xdebug** and debugging tools
- Teach **WordPress hook inspection**
- Teach **REST API debugging**
- Teach **React component debugging**
